# 分析架构与查询口径说明（个人报告）

本文档用于维护 `credit_report_demo` 当前分析架构、查询口径和已知差异，作为后续迭代基线。
计算口径的唯一基线见：
`docs/calculation_scope_baseline_v1.md`

## 1. 当前分析架构（落地版）

采用分层链路：

1. 原始输入层
   - `XML`：主数据源
   - `PDF`：展示证据与说明
   - `mapping/official_code_tables.by_field.individual_v1.json`：码值语义
2. 标准事实层
   - 产物：`individual.standard.enriched_labels.json`
   - 规则：XML 值 + 码表语义优先，PDF 仅兜底
3. 核心表层
   - 产物：`individual.core_tables.json`
   - 表：`report_basic / identity_info / residence_info / occupation_info / credit_summary / credit_account / account_history / query_record / special_transaction / guarantee_record / public_record / objection_record`
4. 语义层
   - `semantic/schema_metadata.json`
   - `semantic/metric_catalog.json`
5. 查询层
   - 文件：`structured_query.py`
   - 流程：`问题 -> query_plan -> plan校验 -> 核心表执行 -> query_result`
6. 回答层
   - 统一字段：`answer / confidence / evidence_paths / verifier_status / cannot_answer_reason / answer_mode / query_plan / query_result`

## 2. 查询记录相关对象定义

### 2.1 `PC05`（查询记录概要信息单元）

- 报告位置：`（七）查询记录概要`
- 语义：概要统计，直接给出固定窗口指标（如最近1个月、最近2年）。
- 特征：强展示口径，不一定可从明细按同一规则完全回算。

### 2.2 `PH01`（查询记录明细）

- 报告位置：`（八）查询记录明细`
- 语义：逐笔记录（日期、机构、查询原因、机构类型）。
- 特征：适合自定义窗口统计（例如近6个月分布）。

## 3. 当前“查询次数（时间窗可变）”实现口径

实现位置：`structured_query.py::_run_query_count_6m`（`query_window_stats`）  
多窗口实现：`structured_query.py::_run_query_multi_window`（`query_multi_window_stats`）

当前规则：

1. 取 `query_record`（源自 `PH01`）
2. 以 `report_basic.report_time` 为基准
3. 时间窗按问题自动识别（1/3/6/12/24个月），采用自然月口径且含起止边界日
4. 返回总次数、原因分布、以及小贷/融资担保/融资租赁机构查询次数（含“融资租凭”等异常写法）
5. 对 1 个月和 24 个月窗口，新增 `PC05 vs PH01` 可比字段对账（`summary_detail_reconciliation`）

补充：

1. 当问题同时包含多个窗口（如“近1年、近2年”）时，使用 `query_multi_window_stats` 返回各窗口并列结果。  
2. 默认时间窗口径为自然月，且包含起止边界日（例如 `2025-10-15` 到 `2026-04-15`）。

示例（`builtin_individual_001`，近6个月）：

- 时间窗：`2025-10-15` 至 `2026-04-15`
- 统计结果：`57`
- 分布：`贷款审批(42), 担保资格审查(9), 信用卡审批(5), 保前审查(1)`

## 3.1 当前“未结清/未销户余额”实现口径（已按报告说明收口）

实现位置：`structured_query.py::_run_outstanding_balance`

已对齐报告说明：

- 对齐条款：报告说明第 7 条
- 原文要点：信贷交易授信及负债信息概要展示的是“未结清/未销户”的授信及负债信息

实现规则：

1. 优先使用 `PC02` 概要指标（来自 `credit_summary`）
2. 余额由以下指标构成：
   - 主口径（未结清账户余额）：`PC02BJ01 + PC02EJ02 + PC02FJ02 + PC02GJ02 + PC02HJ04 + PC02IJ04`
   - 扩展口径（未结清相关负债余额）：主口径 + `sum(PC02KJ02)`
3. 如缺失 `PC02` 指标，回退到 `credit_account` 明细代理口径，并标记为代理规则结果

说明：

- 输出中会区分“未结清账户余额（不含相关还款责任）”与“含相关还款责任的相关负债余额”。
- 金额按人民币口径展示（对应报告说明第 18 条：除特殊币种场景外，报告金额按折合人民币展示）。

## 4. 已确认问题：`PC05` 与 `PH01` 统计口径差异

在当前样例中已确认：

- `PC05` 出现“最近1个月本人查询=13”
- `PH01` 明细未完整体现同口径记录

因此，以下情况会出现差异：

1. 用 `PH01` 回算得到的结果，与 `PC05` 展示值不一致
2. 用户按“概要”理解提问，但系统按“明细”口径回答

这不是单纯代码 bug，也包含原始数据口径差异问题；产品侧必须在答案中显式说明数据来源口径。

## 5. 建议的查询路由策略（下一步）

建议接入双口径路由与校验：

1. 问“最近1个月/最近2年查询次数、机构数”：
   - 优先 `PC05`（概要口径）
2. 问“近6个月/自定义窗口/原因分布”：
   - 使用 `PH01` 明细回算
3. 当两者可比且不一致时：
   - 返回双结果
   - `verifier_status=partially_answerable`
   - `cannot_answer_reason=query_scope_mismatch_pc05_vs_ph01`
   - 在 `answer` 中明确“口径差异，需人工核验”

## 5.1 借款金额 vs 余额 vs 授信总额（已区分）

当前系统已显式区分以下三类问题：

1. “未结清账户余额合计”
   - 口径：`PC02BJ01 + PC02EJ02 + PC02FJ02 + PC02GJ02 + PC02HJ04 + PC02IJ04`
2. “未结清账户借款金额合计（借款金额字段）”
   - 口径：`credit_account.original_amount` 明细字段口径
   - 范围：非循环贷账户 + 循环额度下分账户
   - 过滤：未结清（`close_date` 为空）
   - 输出说明：
     - 账户数/当前余额：按上述范围全部账户统计
     - 借款金额合计：剔除 `呆账/核销` 后汇总
3. “未结清账户授信总额”
   - 口径：`PC02EJ01 + PC02FJ01 + PC02GJ01`
   - 说明：这是概要授信口径，不等于明细“借款金额字段口径”

## 11. 下一阶段升级思路（组合查询能力）

当前 `structured_query` 已优于早期固定 tool，但仍以规则命中单指标为主；复杂复合问句（“总量+分组+窗口+口径解释”）会出现覆盖不足。下一阶段按三层升级：

### 11.1 子意图拆解（Question -> SubPlans）

目标：一条问题可拆为多个子计划，而非单一 metric 命中。

示例：

- 问题：“信用卡数量多少，不同类型分别有几个？”
- 拆解：
  1. 总量子意图：信用卡总数  
  2. 分组子意图：按卡类型分组统计（贷记卡/准贷记卡）

### 11.2 参数化执行器（Plan -> Generic Query）

目标：将“每题写新 query”升级为“通用执行模板 + 参数”。

核心参数：

- `scope`（summary/detail/hybrid）
- `filters`
- `window`
- `group_by`
- `measures`（count/sum/max 等）

执行器依据参数在核心表中受控执行，不允许自由 SQL，保留白名单和口径校验。

### 11.3 指标编排器（SubResults -> Final Answer）

目标：把多个子结果合并为一个可读、可追溯答案。

输出要求：

- 主结论（先总后分）
- 口径说明（包含/不包含）
- 冲突提示（概要 vs 明细）
- 数据质量声明（可答/部分可答/不可靠）

### 11.4 与“直接让模型写 SQL”的关系

本质目标一致，都是提升灵活查询能力；当前路线选择“`query_plan + 参数化执行器`”是更可控的工程化实现，特别适合征信场景的强口径约束与审计需求。

### 11.5 分期落地建议

1. 第一期（低风险）  
   - 参数化执行器先覆盖高频复合问题（如信用卡分类型、查询分窗口+分原因）
   - 保留现有指标护栏与回归测试
2. 第二期（能力扩展）  
   - 子意图自动拆解
   - 指标编排器统一合并多子结果
3. 第三期（可选）  
   - 在强校验前提下引入受限 SQL 生成（非默认）

## 12. 解释层设计（当前共识）

目标：不是让大模型重新算数，而是让大模型“解释已计算结果”。

### 12.1 三层输入

1. `query_result`：确定性结果（数字真值）  
2. 中文口径规则卡：说明“这个结果怎么来的”  
3. PDF 说明片段：报告说明依据（单位、未结清定义、折算规则、概要含义等）

### 12.2 职责边界

1. 结构化层负责算数与口径约束。  
2. 大模型负责业务解释、分段表达、风险提示。  
3. 大模型不得新增未计算指标，不得改动数字/结论。

### 12.3 中文口径卡要求

每个 metric 必须有中文主描述，不以英文缩写作为主解释。建议字段：

1. 指标名称（中文）  
2. 问题含义（中文）  
3. 统计范围（包含）  
4. 排除范围（不包含）  
5. 计算步骤（1/2/3）  
6. 数据来源（中文表名+字段名）  
7. 常见误解（如借款金额≠余额）  
8. 建议回答模板

### 12.4 PDF 说明片段注入策略

推荐方案：小型知识库，而非整份 PDF 直接塞上下文。

1. 先把模板 PDF 说明区切成“说明卡片”  
2. 每条卡片带 `topic + applies_to_metrics`  
3. 回答时按 `metric_name + 问题意图` 检索 2~4 条注入

当片段总量很小（<20 条）时，可先直接放上下文；后续应迁移到检索注入。

当前实现补充：

1. 解释层规则选择器：`explanation_knowledge.py`。  
2. structured_query 润色链路已注入“中文口径规则卡 + PDF说明片段”。  
3. 对外知识文档：`docs/pdf_field_knowledge_v1.md`。

## 8. 口径规范 V1（核心摘要）

本节是“口径规范 v1”的架构级约束摘要；问题级 SQL 细则见
`docs/metric_definition_catalog.md`。

### 8.1 八类需求范围

1. 逾期情况  
2. 授信情况（贷款）  
3. 授信情况（信用卡）  
4. 个人身份信息  
5. 查询情况  
6. 五级分类  
7. 担保/相关还款责任  
8. 异议情况

### 8.2 统一执行原则

1. 先判问题类型，再选口径，不跨口径混算。  
2. “借款金额 / 余额 / 授信总额”强制分离。  
3. 查询类默认明细口径（PH01），概要口径（PC05）单独标注。  
4. 担保/相关还款责任不并入本人账户余额主口径。  
5. 回答必须写清“包含什么、不包含什么”。  
6. 无法计算时禁止硬算，返回 `partially_answerable/not_answerable`。

### 8.3 关键主口径（V1）

1. 逾期统计  
   - 默认口径：`account_history` 明细，按“账户-月份”统计。  
   - 时间窗：按问题自动识别（6/12/24个月，默认24个月）。  
   - 逾期状态：1–7 视为逾期；N/C/*/# 等不计入逾期次数。

2. 未结清账户余额  
   - 主口径：`PC02BJ01 + PC02EJ02 + PC02FJ02 + PC02GJ02 + PC02HJ04 + PC02IJ04`。  
   - 扩展口径：主口径 + `PC02KJ02`（相关还款责任余额）。

3. 未结清借款金额（借款金额字段口径）  
   - 来源：`credit_account.original_amount`。  
   - 范围：非循环贷账户 + 循环额度下分账户。  
   - 过滤：`close_date` 为空；剔除 `呆账/核销`。

4. 未结清授信总额  
   - 概要口径：`PC02EJ01 + PC02FJ01 + PC02GJ01`。  
   - 注意：该口径不等于“借款金额字段口径”。

5. 查询统计  
   - 时间窗统计（如近6个月）默认明细 `PH01`。  
   - 最近1个月/最近2年概要指标默认 `PC05`。

### 8.4 冲突与解释规则

1. `PH01` 与 `PC05` 冲突时：主答明细，补充概要并提示“口径差异”。  
2. “账户余额”与“相关负债”必须双口径分开展示。  
3. 金额默认按报告说明第18条的人民币折算口径展示。  
4. 回答模板建议统一：
   - 时间窗口  
   - 统计口径（包含/不包含）  
   - 结果与明细  
   - 风险提示（脱敏/异议/口径差异）
